# Windows 训练与调参手把手教程（v2）

> 适用分支：`yy`；接口版本：`bev_nav_v2`。本页替代旧操作步骤，历史 v1 日志与旧模型仍保存在 `docs/reports/windows_original/` 和 `training/runs/`。

## 1 环境与路径

Windows 项目位于 `D:\Personal\projects\RL-indoor-nav`。所有命令在 PowerShell 中执行，统一使用 `.\run.cmd`，不要直接调用系统 Python。

```powershell
cd D:\Personal\projects\RL-indoor-nav
.\run.cmd doctor
.\python.cmd -m pytest training\tests\unit -q --basetemp=.tmp\pytest
```

`doctor` 应显示 Python 3.10、torch 2.8 CPU、SB3 2.9.2、Gymnasium 1.4.0 和 2056 维观测。Windows 不运行 ROS/Gazebo。

## 2 v2 语义先看这四点

1. 量程内有限值才是命中；`+inf` 是无回波；NaN、`-inf`、低于 `min_range`、高于 `max_range` 都是未知。未知不会被 BEV 或保护当作空闲。
2. 保护按运动方向和制动扫掠角域检查覆盖。前方缺测禁止前进，后方缺测禁止倒车，纯旋转要求全周已知。
3. 卡死按持续无进展判定，角速度大不再豁免；只有朝局部目标转向且航向误差下降时才有有限宽限期。
4. `spec_version` 已升为 `bev_nav_v2`。旧 v1 权重不能普通 `--resume`，只能 `--init-from` 显式初始化并记录来源。

## 3 固定样例与短检查

```powershell
.\run.cmd fixtures
.\.venv\Scripts\python.exe training\scripts\plot_fixtures.py
```

生成 11 个样例（含 `above_max`），输出 `docs/reports/yy_v2/bev_fixtures.png`。fixtures 是 C++ BEV 对照输入，不等于 C++ 已通过。

## 4 训练 v2 对比模型

固定前视基线：

```powershell
.\run.cmd --config config\yy_v2_fixed50k.yaml train `
  --name yy_v2_fixed_s42 --steps 50000 --seed 42 --run-root experiments\yy_v2\runs
```

自适应局部目标：

```powershell
.\run.cmd --config config\yy_v2_adaptive50k.yaml train `
  --name yy_v2_adaptive_s42 --steps 50000 --seed 42 --run-root experiments\yy_v2\runs
```

把 `--seed` 换成 43、44 得到三个独立种子。两种配置只有 `goal_selection.mode` 不同；网络、输入维度、场景权重、训练预算和种子一致。

- `fixed`：固定 1.2 m 前视，复现旧规则。
- `adaptive`：按路径转角缩短前视，并在前视范围内回退到与路径走廊一致的路线点。规则只使用参考路径和位姿，不使用障碍真值；部署参考在 `training/scripts/deployment/route_goal.py`。
- 训练目录包含 `config.yaml`、`obs_spec.yaml`、`metadata.json`、`source/navrl` 快照、验证历史和权重哈希。
- 已有同名目录会拒绝覆盖；每次实验使用新名称。

显式初始化旧权重：

```powershell
.\run.cmd --config config\yy_v2_adaptive50k.yaml train `
  --name yy_v2_adaptive_init_v1_s42 `
  --init-from training\runs\split_mixed_100k_s42\best_model.zip `
  --run-root experiments\yy_v2\runs
```

程序会写 `initialization.json`：源权重哈希、源步数、源/新 spec 哈希，且重置优化器和步数。不能用它冒充普通续训。续训兼容检查在创建目录之前完成。

## 5 评估协议

- `diagnostic`：开发诊断集（现有 32 个任务），只用于排查，不作为最终结论。
- `validation`：分场景固定种子，用于选型。
- `test`：独立种子，配置冻结后才运行，不参与调参。

分场景验证：

```powershell
.\run.cmd evaluate --model experiments\yy_v2\runs\yy_v2_adaptive_s42\best_model.zip `
  --split validation --episodes 8 `
  --stages empty single turn clutter dense tight_turn protective `
  --output experiments\yy_v2\evaluations\validation\yy_v2_adaptive_s42
```

冻结后测试：

```powershell
.\run.cmd evaluate --model experiments\yy_v2\runs\yy_v2_adaptive_s42\best_model.zip `
  --split test --episodes 12 `
  --stages empty single turn clutter dense tight_turn protective `
  --output experiments\yy_v2\evaluations\test\yy_v2_adaptive_s42
```

安全消融只加 `--no-safety`；不传时尊重模型配置。effective config 会写入评估目录，和实际执行一致。

评估目录重点看：

- `summary.json`：总体与分场景成功率、碰撞率、干预时长、失败原因、请求/执行速度。
- `episodes.csv`：逐回合指标。
- `trajectory_*.npz`：轨迹、原始动作、请求速度、执行速度、干预原因。
- `scenario_metrics.png`、`failure_reasons.png`、`speed_profiles.png`、`trajectories.png`。
- `evaluation_config.yaml` 与 `evaluation_metadata.json`：有效配置、模型哈希、版本和代码版本。

## 6 导出

```powershell
.\run.cmd export --model experiments\yy_v2\runs\yy_v2_adaptive_s42\final_model.zip `
  --name yy_v2_adaptive_final_s42 --output-root models
```

导出先写 `.tmp/export_*`，在隔离子进程中只使用运行目录的 `source/navrl` 生成 fixtures、加载模型和验证；校验通过后原子移动。`final` 不附带 best 成绩；`best` 只有在 `best_validation.json` 的权重哈希匹配时才绑定成绩。旧 v1 运行缺少权重哈希时不会把 best 标记为已绑定。

## 7 调参入口

| 目标 | 配置/函数 |
|---|---|
| 前视规则 | `environment.lookahead`、`environment.goal_selection` |
| 场景比例 | `environment.stage_weights`；先固定场景再重采样任务 |
| 新场景 | `navrl/env.py → _make_layout`；`dense`、`tight_turn`、`protective` |
| 卡死 | `stuck_seconds`、`turn_grace_seconds`、`turn_rate_threshold`、`progress_epsilon` |
| 保护 | `safety.margin`、`reaction_time`、`brake_deceleration`；覆盖规则在 `navrl/control.py` |
| 奖励 | `reward.*`；干预与动作偏差默认 0 |
| PPO | `ppo.*`；网络结构改变必须新实验 |

奖励实验一次只改一类因素：

```powershell
.\run.cmd --config config\yy_v2_reward_intervention30k.yaml train `
  --name yy_v2_reward_intervention_s42 --seed 42 --run-root experiments\yy_v2\runs
.\run.cmd --config config\yy_v2_reward_deviation30k.yaml train `
  --name yy_v2_reward_deviation_s42 --seed 42 --run-root experiments\yy_v2\runs
```

判断改善时同时看成功率、碰撞率、干预时长和请求/执行速度；少干预但更多碰撞不算改善。

## 8 常见失败

- `Config spec_version must be bev_nav_v2`：旧配置不能用于新训练；用当前配置或显式 `--init-from`。
- `Resume ... spec differs`：观测/保护/终止语义变了；改用 `--init-from` 或从头训练。
- `Could not generate reachable task`：检查 `layout_attempts`、`task_attempts`、场景几何和 `room_half_size`。
- 成功率低但碰撞为 0：先看 `failure_reasons` 和请求/执行速度，区分卡死、超时与保护停车。
- 评估目录已存在：换 `--output`，不要覆盖旧结果。
