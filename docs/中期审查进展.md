## 2 启动方式

PPO 闭环（Gazebo + BEV + 策略 + 安全 + RViz）：

```bash
cd ~/ROS2hw
./setup/run_rl_nav.sh
```

可选参数：

```bash
./setup/run_rl_nav.sh rviz:=false                 # 不启动 RViz
./setup/run_rl_nav.sh goal_x:=1.5 goal_y:=0.0     # 修改 odom 坐标系目标
./setup/run_rl_nav.sh model_id:=split_empty_pretrain_v1
./setup/run_rl_nav.sh policy:=false               # 只启动仿真与安全节点，手工发布 /cmd_vel_rl
```

### 2.2 Nav2 基线（居家地图 + AMCL + safety）

```bash
cd ~/ROS2hw
./setup/run_nav2_home.sh
```

启动内容：`robocup_home.world`、`map_server`、`amcl`、Nav2 规划/控制/恢复、`velocity_smoother`、`safety_node`、RViz。AMCL 初始位姿在 launch 内固定为课程机器人的出生点，无需手工点 `2D Pose Estimate`。

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 0.0, y: 0.0}, orientation: {w: 1.0}}}}"
```

速度链路：

```text
controller_server / behavior_server → /cmd_vel_nav
        → velocity_smoother → /cmd_vel_nav_smoothed
        → safety_node → /cmd_vel → Gazebo 底盘
```

### 2.3 录制演示视频

X11 抓屏在 VMware 下只能得到全黑画面，因此视频由 Gazebo 俯视相机生成：

```bash
./setup/run_nav2_home.sh rviz:=false            # 终端 1
ros2 launch project_bringup demo_capture.launch.py \
  output:=$HOME/ROS2hw/experiments/videos/nav2_home_raw.mp4   # 终端 2
ros2 action send_goal ...                       # 终端 3，发送目标
```

录像节点订阅 `/camera/image_raw`，用 OpenCV 写成 mp4；关闭 `gzclient` 后相机约 5 Hz，最终视频插值到 15 fps。

## 3 本轮实现的内容

- `ros2_ws/src/bev_pkg`：C++ BEV 核心与节点。按 `training/envs/navrl/observation.py` 的合同实现雷达重采样、射线栅格化、机器人足迹、欧氏距离变换、目标与运动标量；发布 `/policy_observation` 与 `/bev_grid`。
- `ros2_ws/src/safety_pkg`：C++ 安全节点。订阅候选速度与激光，输出唯一 `/cmd_vel`（20 Hz），包含命令过期、传感器过期、足迹间距、制动距离预判、锁存急停与 `/safety/reset`。
- `ros2_ws/src/project_bringup`：`rl_nav.launch.py` 一键启动 PPO 演示；`nav2_nav.launch.py` 启动居家地图 Nav2 并把速度出口交给 safety；`demo_capture.launch.py` 启动俯视相机与录像节点；`rviz/rl_nav.rviz` 显示激光、BEV 栅格与机器人模型。
- `ros2_ws/src/project_bringup/models/overhead_camera`：不依赖 GUI 的俯视相机模型，供无 X11 抓屏环境生成视频。
- `ros2_ws/src/bev_pkg/test`：固定样例导出脚本与 C++ 校验程序，用于 Windows/Python 与 Ubuntu/C++ 的观测一致性验收。
- `setup/run_rl_nav.sh`、`setup/run_nav2_home.sh`：叠加课程工作空间与项目工作空间后启动演示。

## 4 环境适配记录

这些是本机安装时的实际偏差，复现时需要注意：

| 现象 | 处理 |
|---|---|
| `download.pytorch.org` 下载 184 MB 的 torch 卡住 | 改用阿里云 `pytorch-wheels` 镜像安装同一 wheel，版本仍为 2.8.0+cpu |
| Stable-Baselines3 导入 `cv2` 失败（系统 OpenCV 基于 numpy 1.x） | 保留 numpy 2.2.6（模型序列化依赖），在 venv 内安装 `opencv-python-headless` |
| numba 0.63 与系统 coverage 6.2 不兼容 | 在 venv 内升级 `coverage>=7.4` |
| 策略节点把观测判为无效 | Gazebo `/clock` 比激光时间戳滞后约 50 ms，年龄下限由 0 s 放宽到 -0.15 s，上限仍为 0.5 s |
| 策略到达目标后继续绕圈 | 策略节点增加 `goal_stop_radius`（默认 0.3 m），进入半径后发布零速度 |
| VMware 下 `ffmpeg x11grab` / `xwd` 抓到全黑画面 | 改为在 Gazebo 内放俯视相机，用 `record_video.py` 录 ROS 图像 |
| 居家地图出生点位于地图边界，global costmap 报 `Robot is out of bounds` | 非致命告警；AMCL 与规划仍正常，后续可把地图向外扩一格 |
| safety 只允许前进，Nav2 的倒车恢复被截断 | 当前靠原地旋转恢复；若正式实验需要倒车，再给 safety 增加反向制动检查 |

## 5 尚未完成

1. PPO 模式的全局路径与局部子目标：训练时观测里的 goal 是 A* 路径上 1.2 m 的前视点，当前部署直接给最终目标，长距离或拐角任务存在训练/部署语义偏差。需要 `route_manager` 调用 Nav2 `ComputePathToPose`，再由 `local_goal_node` 输出前视点。
2. PPO 模式加载地图与 AMCL、模式状态机、实体重置流程。
3. 自建并保存一张正式地图，验证重启后加载（当前居家地图来自课程包）。
4. `evaluation_pkg` 的接触检测、任务清单、CSV、轨迹与 rosbag 自动记录。
5. A/B/C 正式实验、统计图表与消融。

## 6 策略侧待确认

1. 控制频率与动作保持：训练 `robot.dt=0.1`，部署按观测到达即推理（约 10 Hz），safety 以 20 Hz 重采样，是否与训练一致。
2. 前视目标语义：训练用路径前视点（`environment.lookahead=1.2`），部署需要同样按路径给局部目标，而不是直接给最终目标。
3. 成功判定：训练要求进入 0.3 m 并保持 1.0 s；部署当前进入 0.3 m 即发布零速度，是否应保持 1.0 s 再停。
4. 目标距离上限：训练目标距离 1.5–4.0 m，居家地图单段任务可能超过 4 m，建议训练端补充长距离与多房间布局。

## 7 已知风险

- 本机为 VMware 软件渲染，`gzclient`、`rviz2` 存在 OpenGL 警告；无界面运行更稳定，评测时建议 `rviz:=false`。
- 当前 32×32 模型来自 Windows 二维环境，Gazebo 成功仅说明策略可闭环，不能替代正式实验结论。
- 安全节点为圆形足迹近似，尚未实现按航向扫掠的矩形足迹。
- 居家地图为课程包提供，不能作为“自建地图”写入正式结论。
