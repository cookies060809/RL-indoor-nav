# 虚拟机导入步骤

## 1 传递哪个文件

传递 `project_vm_20261115.tar.gz`，不要复制 Windows 的 `.venv`。压缩包内部顶层目录是 `project`，解压后目录结构与方案一致。

文件先复制到 VMware 共享文件夹，再复制或解压到 Ubuntu 本地磁盘。共享目录的实际挂载名以你的虚拟机为准，可用以下命令查看：

```bash
ls /mnt/hgfs
```

下面以挂载目录 `/mnt/hgfs/share_file` 为例；如果显示的名称不同，替换该部分。新建一个独立的导入目录，不覆盖现有 `~/ros2_ws`。

```bash
mkdir -p ~/ROS2_project_import
tar -xzf /mnt/hgfs/share_file/project_vm_20261115.tar.gz -C ~/ROS2_project_import
cd ~/ROS2_project_import/project
python3 training/scripts/verify_project.py
```

传输包旁的 `.sha256` 文件用于检查压缩包传输是否完整。将两份文件放在同一目录后，使用 `sha256sum -c project_vm_20261115.tar.gz.sha256`。项目内的 FILE_MANIFEST.json 检查解压后的文件；请在修改文件或生成新报告前做完整校验。

## 2 安装 Linux 专用环境

```bash
cd ~/ROS2_project_import/project
bash training/scripts/setup_ubuntu.sh
```

脚本使用 Ubuntu 自带 Python 3.10，创建 `project/.venv` 并允许读取系统 ROS Python 包，安装 torch 2.8 CPU 与核心锁文件，随后逐个检查三个模型包。安装需要网络，不执行系统 apt 或修改软件源。

如果缺少 Python venv 模块，需要先由你在 Ubuntu 安装 `python3.10-venv`；如果下载失败，保留错误信息再排查。不要使用 sudo pip，也不要把 Windows 的库目录复制进去。

Windows 已验证三个模型包；Linux 上必须重新看到：

```text
PASS: manifest hashes and deterministic inference reference
PASS: rclpy and SB3 import in the same interpreter
PASS: 3 model bundles
```

没有 rclpy 不能算 ROS 运行环境通过，但模型本身仍可先检查。

## 3 检查训练与测试代码

```bash
bash run.sh doctor
PYTHONPATH="$PWD/training/envs" .venv/bin/python -m pytest training/tests/unit -q --basetemp="$PWD/.tmp/pytest"
```

pytest 是开发依赖，核心锁文件没有携带。若要在 Ubuntu 运行测试，先执行 `.venv/bin/python -m pip install 'pytest>=8,<9'`。只验证策略推理不需要安装 pytest。

训练或评估的配置参数 `--config` 放在子命令前。例如：

```bash
bash run.sh --config config/split_mixed32.yaml train \
  --name ubuntu_continue_s42 --steps 10000 --seed 42 \
  --resume training/runs/split_mixed_100k_s42/best_model.zip
```

实际长训仍推荐 Windows。Ubuntu 中的这条命令用于确认代码可迁移，不应与 Gazebo 正式计时实验同时运行。

## 4 编译消息与策略包

```bash
bash training/scripts/build_ros_interfaces.sh
```

脚本只在新交付的 `project/ros2_ws` 中选择构建 project_msgs 和 rl_nav_pkg，使用刚建立的 Linux Python 环境。`wpr_simulation2` 等说明目录不会作为已实现的 ROS 包参与编译。

如果之前已在别处实现过同名包，先比较源码，选择一套工作空间使用，不覆盖已有成果。原课程仿真仍可从 `~/ros2_ws` 启动，项目新增包作为另一层工作空间加载。

## 5 单独启动策略节点

先保证你已有 `/policy_observation` 发布者，并接好独立 safety_node；仅有本包不会产生激光 BEV 或驱动机器人。先检查模型消息接口，再接入完整导航。

```bash
bash training/scripts/run_policy.sh split_empty_pretrain_v1
```

换混合模型：

```bash
bash training/scripts/run_policy.sh split_mixed_pretrain_v1
```

脚本显式使用 `.venv/bin/python` 运行节点，防止 ROS 系统 Python 找不到 PyTorch。输出仅为 `/cmd_vel_rl`，最终 `/cmd_vel` 仍必须由你在虚拟机验证过的安全节点独占。

## 6 虚拟机中仍需完成

1. 复用课程 wpr_simulation2，记录提交号，完成地图保存与重新加载。
2. 根据 TF 核实雷达平面外参、角度序列、机器人足迹与动作周期。
3. 开发 C++ BEV，对照 training/tests/fixtures 中的期望观测。
4. 实现主动全局规划、子目标、安全过滤与唯一速度出口。
5. 验证实体位姿、速度、定位和历史状态的完整重置。
6. 依次测试空场景、单障碍、转角和完整路径，再开展正式实验。

本次整理没有在 Ubuntu 安装依赖、执行 colcon 或运行 Gazebo。首次导入先完成上述检查，再记录实际通过项。
